# GitLab Integration

## Authentik Part

### Create a property mapping

Go to Customization → Property Mappings → Create → Scope Mapping

| Field      | Value           |
| ---------- | --------------- |
| Name       | `GitLab Groups` |
| Scope name | `gitlab_groups` |
| Expression | *(see below)*   |

```python
groups = []
user_groups = request.user.ak_groups.all()
user_group_names = [g.name for g in user_groups]

is_lector = "Lectors" in user_group_names
is_student = "Students" in user_group_names

for group in user_groups:
    if group.name in ["Lectors", "Students"]:
        continue
    
    if group.name.startswith("sk"):
        if is_lector:
            groups.append(f"{group.name}-lectors")
        elif is_student:
            groups.append(f"{group.name}-students")

return {
    "groups": groups,
    "email": request.user.email,
    "username": request.user.username,
    "name": request.user.name
}
```

Output structure of mapping:

| User's Groups         | Emitted Claim      |
| --------------------- | ------------------ |
| `Lectors`, `sk25-26`  | `sk25-26-lectors`  |
| `Students`, `sk25-26` | `sk25-26-students` |
| `Lectors`, `sk26-27`  | `sk26-27-lectors`  |

| Tab                            | Field              | Value                                                                      |
| ------------------------------ | ------------------ | -------------------------------------------------------------------------- |
| **General**                    | Name               | `GitLab OIDC`                                                              |
|                                | Authorization flow | `default-provider-authorization-explicit-consent`                          |
|                                | Client type        | `Confidential`                                                             |
|                                | Client ID          | *(auto-generated, copy it)*                                                |
|                                | Client Secret      | *(auto-generated, copy it)*                                                |
|                                | Redirect URIs      | `https://gitlab.yourdomain.com/users/auth/openid_connect/callback`         |
| **Advanced protocol settings** | Scopes             | Add `gitlab_groups` (custom scope)                                    |

<Note>
    Make sure the openid, profile, email, and custom gitlab_groups scopes are included.
</Note>

## GitLab Part

### Enable OmniAuth OpenID Connect

Edit `/etc/gitlab/gitlab.rb`

```ruby
# /etc/gitlab/gitlab.rb
gitlab_rails['omniauth_enabled'] = true
gitlab_rails['omniauth_allow_single_sign_on'] = ['openid_connect']
gitlab_rails['omniauth_block_auto_created_users'] = false
gitlab_rails['omniauth_auto_link_ldap_user'] = false
gitlab_rails['omniauth_auto_link_saml_user'] = false
gitlab_rails['omniauth_providers'] = [
  {
    name: "openid_connect",
    label: "Authentik",
    icon: "https://auth.pve99.internal/static/dist/assets/icons/icon.png",
    args: {
      name: "openid_connect",
      scope: ["openid", "profile", "email", "gitlab_groups"],
      response_type: "code",
      issuer: "https://auth.pve99.internal/",
      discovery: false,  # ← disable
      uid_field: "sub",
      pkce: true,
      client_options: {
        identifier: "YOUR_CLIENT_ID",
        secret: "YOUR_CLIENT_SECRET",
        redirect_uri: "https://git.pve99.internal/users/auth/openid_connect/callback",
        authorization_endpoint: "https://auth.pve99.internal/application/o/authorize/",
        token_endpoint: "https://auth.pve99.internal/application/o/token/",
        userinfo_endpoint: "https://auth.pve99.internal/application/o/userinfo/",
        jwks_uri: "https://auth.pve99.internal/application/o/gitlab/jwks/"
      }
    }
  }
]
```

```bash
gitlab-ctl reconfigure
```

## Group syncing

Gitlab CE cant sync groups from OIDC provider, so we have to use a workaround. We will use custom webhook server that will listen to OIDC login events and sync groups to Gitlab. You can find the code for this webhook server [here](/docs-static/files/sync.py)

### What we need to do

1. Reads all users and groups from authentik
2. Determines who is a Lector (Maintainer) or Student (Developer)
3. Creates year groups (sk25-26, sk26-27, etc.) in GitLab as top-level groups
4. Adds members with the right access level
5. Removes members who no longer belong
6. Forces any Private projects to Internal visibility

### Setup

The sync script will run alongside the authentik server, by modifying the docker-compose.yml file. You can also run it as a separate service, but you will have to make sure it has access to the authentik database and the GitLab API.

1. Create API tokens
authentik token:

    Go to Directory → Tokens & App passwords
    Create a token for a service account (or use an existing admin)
    Copy the token value

GitLab token:

    Go to Admin Area → Access Tokens
    Create a token with api scope
    Copy the token value

2. Add to your .env file
```bash
AUTHENTIK_API_TOKEN=your-authentik-token-here
GITLAB_API_TOKEN=your-gitlab-token-here
```

3. Copy files
Place this folder next to your docker-compose.yml:
```
├── docker-compose.yml
└── authentik-gitlab-sync/
    ├── Dockerfile
    └── sync.py
```

```dockerfile
FROM python:3.12-slim

WORKDIR /app
RUN pip install --no-cache-dir requests

COPY sync.py /app/sync.py
RUN chmod +x /app/sync.py

CMD ["python", "/app/sync.py"]
```

4. Add the service

Paste the gitlab-sync service from [docker-compose.snippet.yml](/docs-static/files/docker-compose.snippet.yml) into your authentik docker-compose.yml.

5. Start
```bash
docker compose up -d gitlab-sync
```

Watch logs:
```bash
docker logs -f authentik-gitlab-sync
```
